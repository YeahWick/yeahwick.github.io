Debugging Python in Doom Emacs with LSP and DAP

January 15, 2026

Why Debug in Emacs?

If you're already living in Doom Emacs for coding, switching to a different IDE just for debugging feels like a betrayal. The good news is that Doom Emacs has excellent debugging support through the Debug Adapter Protocol (DAP), which works seamlessly with LSP. This guide walks you through setting up and using the debugger for Python, complete with breakpoints, variable inspection, and stepping through code.

Prerequisites: Setting Up Your Doom Config

First, ensure you have the right modules enabled in your ~/.doom.d/init.el:

;; ~/.doom.d/init.el
:tools
debugger          ; FIXME stepping through code, to help you add bugs
lsp               ; M-x vscode

:lang
(python +lsp +pyright)  ; pyright provides excellent type checking

After editing, run doom sync to install the required packages:

doom sync

You'll also need to install debugpy, the Python debugger that DAP uses:

pip install debugpy

Our Example Python Program

Let's create a simple Python program that we'll use to demonstrate debugging features. This program calculates statistics for a list of numbers:

# stats.py - A simple statistics calculator

def calculate_mean(numbers):
    """Calculate the arithmetic mean of a list of numbers."""
    total = 0
    for num in numbers:
        total += num
    return total / len(numbers)


def calculate_variance(numbers):
    """Calculate the variance of a list of numbers."""
    mean = calculate_mean(numbers)
    squared_diffs = []
    for num in numbers:
        diff = num - mean
        squared_diffs.append(diff ** 2)
    return calculate_mean(squared_diffs)


def find_outliers(numbers, threshold=2):
    """Find numbers that are more than threshold std devs from mean."""
    mean = calculate_mean(numbers)
    variance = calculate_variance(numbers)
    std_dev = variance ** 0.5

    outliers = []
    for num in numbers:
        z_score = abs(num - mean) / std_dev
        if z_score > threshold:
            outliers.append(num)
    return outliers


def main():
    data = [10, 12, 23, 23, 16, 23, 21, 16, 100, 18, 21]

    print(f"Data: {data}")
    print(f"Mean: {calculate_mean(data):.2f}")
    print(f"Variance: {calculate_variance(data):.2f}")

    outliers = find_outliers(data)
    print(f"Outliers: {outliers}")


if __name__ == "__main__":
    main()

Starting the Debugger

With your Python file open, start the debugger with:

SPC d d    ; Start debugging session (doom keybind)
M-x dap-debug   ; Alternative command

You'll be prompted to select a debug template. For Python, choose "Python :: Run file (buffer)" to debug the current file.

The first time you run this, DAP will download the debug adapter if needed. You'll see the debugger UI appear with several new windows:

  • Breakpoints: Shows all set breakpoints
  • Locals: Displays local variables in the current scope
  • Stack: Shows the call stack
  • Output: Program output and debugger messages

Setting Breakpoints

Breakpoints pause execution at specific lines so you can inspect the program state. There are several ways to set them:

Toggle Breakpoint at Current Line

SPC d b b  ; Toggle breakpoint at current line
M-x dap-breakpoint-toggle

A red dot will appear in the fringe next to the line number, indicating an active breakpoint.

Conditional Breakpoints

Sometimes you only want to break when a specific condition is met. For example, let's say we want to pause only when num equals 100 in our outlier detection:

SPC d b c  ; Add conditional breakpoint
M-x dap-breakpoint-condition

When prompted, enter the condition:

num == 100

Now execution will only pause at that line when the condition is true.

Log Points (Non-Breaking)

Log points print a message without stopping execution—perfect for printf-style debugging without modifying code:

SPC d b l  ; Add log point
M-x dap-breakpoint-log-message

Enter a log message with expressions in curly braces:

Processing number: {num}, current mean: {mean}

Managing Breakpoints

SPC d b d  ; Delete breakpoint at point
SPC d b D  ; Delete all breakpoints
SPC d b a  ; Add breakpoint (interactive)

Stepping Through Code

Once paused at a breakpoint, you can step through your code line by line:

SPC d n    ; Step over (next line, don't enter functions)
SPC d i    ; Step into (enter function calls)
SPC d o    ; Step out (finish current function, return to caller)
SPC d c    ; Continue (run until next breakpoint)
SPC d r    ; Restart debugging session
SPC d q    ; Quit debugging session

Example: Stepping Through calculate_mean

Let's set a breakpoint at line 5 (inside calculate_mean) and step through:

  1. Open stats.py and navigate to line 5: total = 0
  2. Press SPC d b b to set a breakpoint
  3. Press SPC d d and select "Python :: Run file (buffer)"
  4. Execution pauses at line 5

Now step through the loop:

SPC d n    ; Execute "total = 0", move to line 6
SPC d n    ; Enter the for loop, move to line 7
SPC d n    ; Execute "total += num", move back to line 6

Watch the Locals window update as total accumulates values!

Variable Inspection

Inspecting variables is one of the most powerful debugging features. Doom Emacs with DAP provides several ways to examine your program's state.

The Locals Window

When paused, the Locals window automatically shows all variables in the current scope:

; Example Locals window content when paused in calculate_mean:
;
; numbers: [10, 12, 23, 23, 16, 23, 21, 16, 100, 18, 21]
; total: 166  (after several iterations)
; num: 23

You can expand complex objects by pressing RET on them.

Hover Inspection

Move your cursor over any variable and press:

SPC d e e  ; Evaluate expression at point
M-x dap-eval-thing-at-point

A popup will show the current value. For our example, hovering over numbers would show:

[10, 12, 23, 23, 16, 23, 21, 16, 100, 18, 21]

Evaluate Arbitrary Expressions

Want to check a computed value or test an expression? Use the REPL:

SPC d e r  ; Open REPL
M-x dap-ui-repl

In the REPL, you can evaluate any Python expression in the current context:

>>> total / len(numbers)
27.545454545454547

>>> numbers[0:3]
[10, 12, 23]

>>> [n for n in numbers if n > 50]
[100]

This is incredibly powerful for testing hypotheses about your code's behavior.

Watch Expressions

Add expressions to watch continuously as you step through code:

SPC d e a  ; Add watch expression
M-x dap-ui-expressions-add

Enter an expression like total / len(numbers). The Expressions window will update this value every time execution pauses.

Practical Debugging Session: Finding a Bug

Let's walk through a realistic debugging scenario. Imagine our find_outliers function has a bug—it's returning an empty list when it shouldn't.

Step 1: Set Strategic Breakpoints

Set a breakpoint at the start of find_outliers (line 21):

SPC d b b  ; on line: mean = calculate_mean(numbers)

Step 2: Run the Debugger

SPC d d    ; Start debugging

Step 3: Inspect Initial Values

When paused, check the Locals window to see the input:

; Locals:
; numbers: [10, 12, 23, 23, 16, 23, 21, 16, 100, 18, 21]
; threshold: 2

Step 4: Step Through and Watch Variables

SPC d n    ; Step to calculate variance
SPC d n    ; Step to calculate std_dev

Check the computed values:

; Locals:
; mean: 25.727272727272727
; variance: 548.5619834710744
; std_dev: 23.421398837498356

Step 5: Evaluate a Suspicious Expression

Use the REPL to check if our outlier detection logic is correct:

SPC d e r  ; Open REPL

>>> abs(100 - mean) / std_dev
3.1700...  ; This is > 2, so 100 should be an outlier!

>>> abs(10 - mean) / std_dev
0.671...   ; This is < 2, not an outlier

Step 6: Step Into the Loop

Continue stepping through the loop to verify each number is checked correctly. Set a conditional breakpoint to stop only when processing the outlier:

SPC d b c  ; On line: z_score = abs(num - mean) / std_dev
; Condition: num == 100

Now press SPC d c to continue. Execution will pause only when num is 100, letting you verify the outlier detection logic.

Useful DAP Commands Reference

Here's a quick reference for the most commonly used debugging commands in Doom Emacs:

Session Control

SPC d d    ; Start debugging
SPC d l    ; Debug last configuration
SPC d r    ; Restart session
SPC d q    ; Quit debugging
SPC d Q    ; Disconnect (leave program running)

Stepping

SPC d n    ; Step over (next)
SPC d i    ; Step into
SPC d o    ; Step out
SPC d c    ; Continue
SPC d s    ; Pause/stop

Breakpoints

SPC d b b  ; Toggle breakpoint
SPC d b c  ; Conditional breakpoint
SPC d b l  ; Log point
SPC d b d  ; Delete breakpoint
SPC d b D  ; Delete all breakpoints

Evaluation

SPC d e e  ; Eval at point
SPC d e r  ; REPL
SPC d e a  ; Add watch expression

UI Windows

SPC d w l  ; Locals window
SPC d w s  ; Stack frames window
SPC d w b  ; Breakpoints window
SPC d w o  ; Output window

Configuring Debug Templates

For more complex projects, you may want custom debug configurations. Add them to ~/.doom.d/config.el:

;; ~/.doom.d/config.el

(after! dap-mode
  ;; Configure Python debugging
  (dap-register-debug-template
   "Python :: My Project"
   (list :type "python"
         :args ""
         :cwd "${workspaceFolder}"
         :env '(("DEBUG" . "1"))
         :program "${file}"
         :request "launch"
         :name "My Project Debug"))

  ;; Debug with arguments
  (dap-register-debug-template
   "Python :: With Args"
   (list :type "python"
         :args "--verbose --config config.yaml"
         :cwd "${workspaceFolder}"
         :program "${file}"
         :request "launch"
         :name "Python with Args"))

  ;; Debug a specific module
  (dap-register-debug-template
   "Python :: Module"
   (list :type "python"
         :args ""
         :cwd "${workspaceFolder}"
         :module "mypackage.main"
         :request "launch"
         :name "Debug Module")))

Tips and Tricks

  • Remote Debugging: DAP supports attaching to remote Python processes. Use debugpy.listen(("0.0.0.0", 5678)) in your code and create an attach configuration.
  • Exception Breakpoints: Break on all exceptions with SPC d b e to catch errors before they propagate.
  • Hydra Menu: Press SPC d h to open a hydra menu with all debug commands—great for learning the keybindings.
  • Persistent Breakpoints: Breakpoints are saved per project, so they persist across sessions.
  • Multi-threaded Debugging: DAP handles multiple threads. Use the Stack window to switch between threads.

Troubleshooting

If debugging isn't working, check these common issues:

  • debugpy not found: Run pip install debugpy in your Python environment
  • Wrong Python interpreter: Set python-shell-interpreter or use SPC m e i to set the interpreter
  • DAP not loading: Ensure debugger is enabled in init.el and run doom sync
  • No debug templates: Run M-x dap-debug-edit-template to see available templates

Conclusion

Debugging in Doom Emacs with DAP brings IDE-level debugging capabilities to your favorite text editor. With breakpoints, variable inspection, and the REPL, you can track down bugs without leaving Emacs. The integration with LSP means you get the best of both worlds: intelligent code navigation and powerful debugging in one environment.

The key is practice—set some breakpoints in your next debugging session instead of reaching for print statements. You'll find that stepping through code and inspecting variables gives you a much deeper understanding of what's actually happening in your program.
