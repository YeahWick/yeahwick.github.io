Mutation Testing: How to Know If Your Tests Actually Work

January 16, 2026

The Problem with Code Coverage

You've written tests. Your code coverage is at 95%. Everything is green. Ship it, right?

Not so fast. Code coverage tells you which lines your tests execute, but it doesn't tell you whether your tests actually verify anything meaningful. Consider this test:

def test_add():
    add(2, 3)  # No assertion!

This test "covers" the add function, but it doesn't check the result. The function could return anything and this test would pass. Coverage metrics are useful, but they can give false confidence.

This is where mutation testing comes in.

What Is Mutation Testing?

Mutation testing is a technique that evaluates the quality of your tests by introducing small, deliberate changes (mutations) to your code and checking if your tests catch them. Each mutation simulates a potential bug:

  • Changing + to -
  • Replacing > with >=
  • Swapping and for or
  • Returning None instead of a value

If your tests fail after a mutation is introduced, the mutation is "killed"—your tests caught the bug. If your tests still pass, the mutation "survives"—you have a gap in your test coverage.

The mutation score is the percentage of mutations killed:

Mutation Score = Killed Mutations / Total Mutations

A high mutation score means your tests are actually verifying behavior, not just executing code.

A Practical Example

To demonstrate mutation testing, I built a Python library called mutation-testing. Let's walk through how it works using a simple calculator module.

Here's the code we want to test:

# calculator.py
def add(a: int, b: int) -> int:
    """Add two numbers."""
    return a + b


def subtract(a: int, b: int) -> int:
    """Subtract b from a."""
    return a - b


def is_positive(x: int) -> bool:
    """Check if number is positive."""
    return x > 0


def clamp(value: int, min_val: int, max_val: int) -> int:
    """Clamp value between min and max."""
    if value < min_val:
        return min_val
    if value > max_val:
        return max_val
    return value

And here are our tests:

# test_calculator.py
def test_add():
    assert add(2, 3) == 5
    assert add(-1, 1) == 0
    assert add(0, 0) == 0


def test_subtract():
    assert subtract(5, 3) == 2
    assert subtract(1, 1) == 0


def test_is_positive():
    assert is_positive(5) is True
    assert is_positive(-1) is False
    # Note: Missing test for 0 - mutation will survive!


def test_clamp():
    assert clamp(5, 0, 10) == 5
    assert clamp(-5, 0, 10) == 0
    assert clamp(15, 0, 10) == 10

These tests look reasonable and would give 100% coverage. But let's see what mutation testing reveals.

Defining Mutations

Mutations are defined in a YAML configuration file:

# mutations.yaml
version: "1.0"

settings:
  timeout: 30

targets:
  - module: calculator
    path: src/calculator.py
    mutations:
      - id: add_to_sub
        function: add
        description: "Replace + with - in add()"
        original: "a + b"
        mutant: "a - b"

      - id: add_to_mult
        function: add
        description: "Replace + with * in add()"
        original: "a + b"
        mutant: "a * b"

      - id: sub_to_add
        function: subtract
        description: "Replace - with + in subtract()"
        original: "a - b"
        mutant: "a + b"

      - id: gt_to_gte
        function: is_positive
        description: "Replace > with >= in is_positive()"
        original: "x > 0"
        mutant: "x >= 0"

      - id: gt_to_lt
        function: is_positive
        description: "Replace > with < in is_positive()"
        original: "x > 0"
        mutant: "x < 0"

      - id: clamp_lower_boundary
        function: clamp
        description: "Off-by-one in lower bound check"
        original: "value < min_val"
        mutant: "value <= min_val"

      - id: clamp_upper_boundary
        function: clamp
        description: "Off-by-one in upper bound check"
        original: "value > max_val"
        mutant: "value >= max_val"

Each mutation specifies the function, what the original code looks like, and what to replace it with. The library uses Python's AST (Abstract Syntax Tree) to find and replace these patterns structurally—not just text search and replace.

Running the Mutation Tests

from mutation_testing import MutationRunner
import calculator

def run_tests():
    """Run test suite, return True if all pass."""
    try:
        assert calculator.add(2, 3) == 5
        assert calculator.subtract(5, 3) == 2
        assert calculator.is_positive(5) is True
        assert calculator.is_positive(-1) is False
        assert calculator.clamp(5, 0, 10) == 5
        return True
    except AssertionError:
        return False

runner = MutationRunner(test_runner=run_tests)
report = runner.run_from_config("mutations.yaml")

print(f"Mutation Score: {report.score:.1%}")

One mutation survived! When we changed x > 0 to x >= 0, the tests still passed. This reveals a gap: we never test what happens when x == 0. Adding this test kills the mutation:

def test_is_positive():
    assert is_positive(5) is True
    assert is_positive(-1) is False
    assert is_positive(0) is False  # This kills the mutation!

How AST Parsing Works

The real magic happens in how mutations are applied. Rather than doing text replacement (which is brittle), the library parses Python code into an Abstract Syntax Tree and performs structural transformations.

What Is an AST?

An AST represents code as a tree of nodes. Each node represents a construct like a function, operator, or value. Here's a simple example:

import ast

source = "return a + b"
tree = ast.parse(source, mode='exec')
print(ast.dump(tree, indent=2))

This produces:

Module(
  body=[
    Return(
      value=BinOp(
        left=Name(id='a', ctx=Load()),
        op=Add(),
        right=Name(id='b', ctx=Load())
      )
    )
  ]
)

The code return a + b becomes a tree with:

  • A Return node containing...
  • A BinOp (binary operation) with...
  • left: A Name node for a
  • op: An Add operator
  • right: A Name node for b

Pattern Matching with AST

To apply a mutation, we need to find where a + b appears and replace it with a - b. The library does this by parsing both patterns into ASTs and comparing them structurally.

Here's the core matching logic:

class PatternReplacer(ast.NodeTransformer):
    """Replace AST patterns structurally."""

    def __init__(self, pattern: ast.AST, replacement: ast.AST):
        self.pattern = pattern
        self.replacement = replacement

    def _matches(self, node: ast.AST, pattern: ast.AST) -> bool:
        """Check if node matches pattern structurally."""
        if type(node) != type(pattern):
            return False

        # Handle Name nodes (variables)
        if isinstance(node, ast.Name):
            return node.id == pattern.id

        # Handle Constants (numbers, strings, booleans)
        if isinstance(node, ast.Constant):
            return node.value == pattern.value

        # Handle Binary Operations (a + b, x * y, etc.)
        if isinstance(node, ast.BinOp):
            return (type(node.op) == type(pattern.op) and
                    self._matches(node.left, pattern.left) and
                    self._matches(node.right, pattern.right))

        # Handle Comparisons (x > 0, a == b, etc.)
        if isinstance(node, ast.Compare):
            if len(node.ops) != len(pattern.ops):
                return False
            if len(node.comparators) != len(pattern.comparators):
                return False
            if not self._matches(node.left, pattern.left):
                return False
            for n_op, p_op in zip(node.ops, pattern.ops):
                if type(n_op) != type(p_op):
                    return False
            for n_cmp, p_cmp in zip(node.comparators, pattern.comparators):
                if not self._matches(n_cmp, p_cmp):
                    return False
            return True

        # Handle Return statements
        if isinstance(node, ast.Return):
            if node.value is None and pattern.value is None:
                return True
            if node.value is None or pattern.value is None:
                return False
            return self._matches(node.value, pattern.value)

        # Generic field comparison
        for field in node._fields:
            if not hasattr(pattern, field):
                return False
            if not self._matches(
                getattr(node, field),
                getattr(pattern, field)
            ):
                return False
        return True

This recursive function walks both trees simultaneously, checking that each node type, operator, and value matches.

Applying Transformations

Once we find a match, we use the NodeTransformer pattern to replace nodes:

def generic_visit(self, node):
    """Visit each node and replace if it matches pattern."""
    # First, transform children
    node = super().generic_visit(node)

    # Then check if this node matches our pattern
    if self._matches(node, self.pattern):
        # Return a deep copy of the replacement
        return copy.deepcopy(self.replacement)

    return node

The transformation happens in place: traverse the tree, find matches, swap them with the replacement, and continue.

Putting It Together

Here's how a mutation gets applied:

def _apply_mutation(source: str, original: str, mutant: str) -> str:
    """Apply a mutation to source code."""
    # Parse everything to AST
    tree = ast.parse(source)
    original_ast = _parse_pattern(original)
    mutant_ast = _parse_pattern(mutant)

    # Transform the tree
    transformer = PatternReplacer(original_ast, mutant_ast)
    new_tree = transformer.visit(tree)

    # Fix any missing location info
    ast.fix_missing_locations(new_tree)

    # Convert back to source code
    return ast.unparse(new_tree)


def _parse_pattern(code: str) -> ast.AST:
    """Parse a code pattern into AST."""
    try:
        # Try as expression first (e.g., "a + b")
        tree = ast.parse(code, mode='eval')
        return tree.body
    except SyntaxError:
        # Fall back to statement (e.g., "return x")
        tree = ast.parse(code, mode='exec')
        return tree.body[0]

This approach is much more robust than text replacement. It handles whitespace differences, comments, and ensures the mutation produces valid Python code.

AST Node Types Reference

Here are the most commonly mutated AST node types:

Binary Operations (ast.BinOp)

# Common mutations:
# Add() -> Sub()     (+  becomes -)
# Sub() -> Add()     (-  becomes +)
# Mult() -> Div()    (*  becomes /)
# FloorDiv() -> Div()  (// becomes /)

# AST structure for "a + b":
BinOp(left=Name('a'), op=Add(), right=Name('b'))

Comparisons (ast.Compare)

# Common mutations:
# Gt() -> GtE()     (>  becomes >=)
# Lt() -> LtE()     (<  becomes <=)
# Eq() -> NotEq()   (== becomes !=)

# AST structure for "x > 0":
Compare(
    left=Name('x'),
    ops=[Gt()],
    comparators=[Constant(0)]
)

Boolean Operations (ast.BoolOp)

# Common mutations:
# And() -> Or()     (and becomes or)
# Or() -> And()     (or  becomes and)

# AST structure for "a and b":
BoolOp(op=And(), values=[Name('a'), Name('b')])

Unary Operations (ast.UnaryOp)

# Common mutations:
# Not() -> (remove)   (not x becomes x)
# USub() -> UAdd()    (-x becomes +x)

# AST structure for "not x":
UnaryOp(op=Not(), operand=Name('x'))

Runtime Mutation Injection

One clever technique the library uses is runtime injection. Instead of modifying source files on disk, it injects mutations directly into running code by manipulating Python's __code__ objects:

class MutationInjector:
    """Inject mutations at runtime without modifying files."""

    def inject(self, func, original: str, mutant: str):
        """Replace function's code with mutated version."""
        # Get the original source code
        source = inspect.getsource(func)

        # Apply the mutation
        mutated_source = _apply_mutation(source, original, mutant)

        # Compile the mutated code
        code = compile(mutated_source, '', 'exec')

        # Extract the function's code object
        for const in code.co_consts:
            if isinstance(const, type(func.__code__)):
                # Swap the code object
                self._original_code = func.__code__
                func.__code__ = const
                return

    def restore(self, func):
        """Restore original function code."""
        if self._original_code:
            func.__code__ = self._original_code

This approach means:

  • No temporary files to clean up
  • Tests run against the actual module in memory
  • Original code is always restored, even if tests crash

Best Practices for Mutation Testing

Start Small

Mutation testing can be slow since it runs your test suite once per mutation. Start with critical modules and expand coverage gradually.

Focus on Boundary Conditions

The most valuable mutations are often around boundaries:

  • > vs >=
  • < vs <=
  • Off-by-one in loops

Don't Chase 100% Mutation Score

Some mutations are equivalent (they don't change behavior) or test trivial code. A mutation score of 80-90% is often sufficient.

Use Mutation Testing in CI

Run mutation tests on changed code in pull requests. This catches regressions in test quality before they merge.

Conclusion

Mutation testing answers the question "do my tests actually test anything?" By introducing deliberate bugs and checking if tests catch them, you gain confidence that your test suite provides real protection against regressions.

The key insights:

  • Code coverage lies—it measures execution, not verification
  • Mutation testing reveals gaps—surviving mutations show where tests are weak
  • AST parsing enables robust mutations—structural transformations beat text replacement
  • Runtime injection keeps things clean—no files to manage, instant rollback

Check out the mutation-testing repository to try it yourself. The documentation includes more examples and a detailed guide on AST manipulation for those who want to dive deeper.
